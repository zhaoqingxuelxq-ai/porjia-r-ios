2  统一接口契约（I 表）
--------------------------------------------------------------------------------

  2.1 三层结构

    调用方（bat / 人） → 编排层（install.sh） → 执行层（minisctl.py / minisctl.py）

    职责不许越界：
      编排层只管  找目录、备份、调用、展示、重启。
      执行层只管  读文件、改文本、验语法、写文件。
      写盘只有执行层做，且原子。

  2.2 统一返回信封

  所有执行层调用的 stdout 必须是且仅是一个 JSON 对象，第一个字节是 {，
  最后一行换行。任何人类可读文字走 stderr，不许混进 stdout。
  这是硬约束 —— 编排层用 ConvertFrom-Json 一次解析，多一个字符就崩。

  信封：
  {
    "schema": "minis.result/1",
    "ok": true,
    "mode": "install",
    "tool": { "name": "minisctl.py", "version": "8.0.0" },
    "data": { ... 该 mode 的业务字段 ... },
    "error": null,                        // 或 { "code": 3, "message": "...", "detail": "..." }
    "timing": { "ms": 1234 }
  }

  兼容原则：信封之外，各 mode 原有的顶层字段（ok / results / checks / marks …）
  一律保留在顶层，老调用方不改也能跑。新代码只读信封。

  2.4 参数解析统一规则

    1. 长参数用 `--key value`。`--key=value` 也认（v8 新增）。
    2. 布尔开关用 `--flag`，出现在参数表里即为 true。
    3. 路径含空格不许自己加引号，由调用方传单个参数，执行层原样收。
    4. 多值用分号分隔：`--initial-fallback "A;B"`。不用逗号（路径里可能有逗号）。
    5. 未知参数忽略，不报错。向后兼容优先于严格。

  2.5 原子写盘

    写 SKILL.md 的顺序，一步不许省：
      同目录临时文件 → 写内容 → fsync → 语法复检 → rename 覆盖
      → 重读字节数比对 → 失败则回滚到 .bak

    现状：临时文件已经放在目标同目录（v3.4 起就是），rename 同分区原子，
    这一层没问题。v8 补的是两处：

      1. 缺 fsync。writeFileSync 只写到内核页缓存，rename 完成、
         进程退出、断电 —— 目标会变成 0 字节或半截文件，而 exit code 是 0。
         加 fs.openSync + writeSync + fsyncSync + closeSync。
      2. 缺落盘比对。写完不验证实际字节数，磁盘满/杀毒锁文件时会静默截断。
         加 statSync(target).size === Buffer.byteLength(payload) 断言，
         不等则从 .bak 回滚并退出码 5。

    这是"报成功但文件坏了"的典型形态，比直接报错危险得多。

  2.6 并发锁

    同目录放 .mv9-lock，内容为 pid + 时间。取锁失败且锁龄 < 60s → 退出码 6。
    锁龄 > 60s 视为残留，直接接管。这是为了防两个 bat 同时点。
