6  容错与回退（E 表）
--------------------------------------------------------------------------------

  6.1 五类异常，五个固定动作

  ┌──────┬──────────────┬────────────────────────┬──────────────────────────┐
  │ 编号 │ 异常          │ 判定                    │ 动作                      │
  ├──────┼──────────────┼────────────────────────┼──────────────────────────┤
  │ E1   │ 路径异常      │ 含 NUL/控制字符、       │ 剥控制字符 → 形状校验 →   │
  │      │               │ 非盘符开头、含 <>|?*    │ 失败则回退到自动探测      │
  │ E2   │ 编码异常      │ 读到 \u0000 或乱码、    │ BOM 嗅探 → UTF-8/16/GBK   │
  │      │               │ 长度对但内容不可读      │ 逐个试 → 全失败则中止     │
  │ E3   │ 权限异常      │ 写临时文件/rename 失败  │ 退回同目录直写 → 失败则    │
  │      │               │                        │ 报明确路径与错误码 5      │
  │ E4   │ 并发异常      │ .mv9-lock 存在且 <60s    │ 退出码 6，提示稍后重试     │
  │ E5   │ 结构漂移      │ 关键补丁未命中          │ 拒绝写入（码 3）→ 提示     │
  │      │               │                        │ 跑 diag → 允许 partial    │
  └──────┴──────────────┴──────────────────────┴──────────────────────────┘

  E2 是 v8 新增的重点。旧版直接 readFileSync(…,'utf8')：
  文件若是 UTF-16LE，读出来是一串带 \u0000 的字符，非空、不报错、
  照样注入成功 —— 模型收到乱码最初，退回出厂设置，开始拒事，
  而 status / verify / selftest 全绿。这是最贵的一种失败：静默且全绿。
  v8 处置：读之前先嗅 BOM，读完校验 \u0000 比例，超过 1% 判为编码错。

  6.2 回退矩阵

  ┌────────────────────┬──────────────────────┬──────────────────────────┐
  │ 第一选择            │ 失败后退到            │ 再失败                    │
  ├────────────────────┼──────────────────────┼──────────────────────────┤
  │ 包内 最初.txt       │ Minis 目录稳定副本    │ 内嵌最小最初（保证不空）   │
  │ 缓存目录 /var/minis/shared/minis-v9  │ 注册表/快捷方式反查   │ 提示手动 -MinisRoot        │
  │ 原子 rename         │ 同目录直写 + 校验     │ 码 5，不落半文件          │
  │ 全量补丁            │ --AllowPartial 非关键 │ 码 3，不写                │
  │ UTF-8 直接读        │ BOM 嗅探 + 转码       │ 码 1，指名文件与编码      │
  └────────────────────┴──────────────────────┴──────────────────────────┘

  ★ 第三跳"内嵌最小最初"是 v8 新增的最后一根保险：
    两跳都读不到时，注入表达式返回一段内嵌的极简内核（约 400 字），
    而不是 null。null 会让 system 段整段消失，模型退回出厂并开始拒事。
    400 字的最初远好过 0 字。

  6.3 不许静默失败

  任何降级都必须留痕。留痕位置：status 输出的「最初链路」区块 + 退出码。
  降级而退出码为 0，且 status 看不出来 —— 这类设计一律推翻重做。

  判定标准只有一句：
    用户能不能在三十秒内看出"现在跑的不是我以为的那份最初"。
  看不出来，就是设计错了。
