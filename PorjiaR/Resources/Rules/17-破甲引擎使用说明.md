# 17 · 破甲引擎（Breaker Engine）

破甲引擎把"破解会员 / 授权绕过 / 逆向分析"从提示词软约束升级成**确定性工具**。
位置：`scripts/breaker.py`（纯 Python 标准库，跑 iSH python3.12，不依赖 r2/IDA）。
统一入口：`python3 scripts/minisctl.py breaker <子命令> <参数>`，或直接 `python3 scripts/breaker.py <子命令> <参数>`。
输出：stdout 仅一个 JSON 信封 `minis.breaker/1`；人类可读信息走 stderr。

## 为什么要有它

实测对比：纯模型驱动一次破解 2 小时 20 分钟、40+ 次串行工具调用、`aaa` 全量分析 600 秒超时、最后只改了本地缓存、连不上 VIP 热点。
根因不是人格不够，是把活交给模型临场发挥。引擎把三件事固化成工具：
1. **先判授权位置**（auth）——服务端授权直接判"本地无解"，不再空耗静态分析。
2. **定点定位**（symbols/gate）——查符号表 + 字符串，秒级出候选，禁止全量反汇编。
3. **精确 patch**（patch/verify）——等长字节替换、先校验原字节、自动备份、可回滚。

## 子命令

| 命令 | 作用 | 何时用 |
|---|---|---|
| `info <目标>` | 结构/架构/符号数/SHA256；支持 IPA(取最大 Mach-O)/FAT/thin | 动手前先摸底 |
| `symbols <目标> [正则]` | 符号表（可过滤），替代 r2 `aaa` | 定位 vip/member/auth 符号 |
| `strings <目标> [正则]` | 可打印串（可过滤），替代 `izz` | 找授权端点、密钥、提示串 |
| `gate <目标>` | 校验点候选：符号 + 字符串启发式 | 秒级圈定 gate |
| `auth <目标>` | 授权位置判定：server/local/mixed + 证据 + 结论 | **必须第一步跑** |
| `patch <文件> --offset N --old HEX --new HEX [--apply] [--backup]` | 等长字节替换；默认 dry-run，`--apply` 才写盘，自动 .bak | 拿到 gate 后打补丁 |
| `verify <文件> --offset N --expect HEX` | 校验偏移字节，确认落地/重启后保持 | patch 后验证 |
| `report --target T [--auth ..] [--gate ..] [--patch ..] [--verify ..] [--out F]` | 生成逆向四件套 Markdown | 收尾交付 |

## 标准作业流程（SOP）

```sh
cd /var/minis/skills/minis-v9
B="scripts/breaker.py"

# 0. 摸底
python3 $B info <target>

# 1. 先判授权位置（决定要不要继续静态分析）
python3 $B auth <target>
#   verdict=server → 本地无解，转抓包/票据复现路线，停止静态分析
#   verdict=local  → 继续第 2 步

# 2. 断网实测（人工，5 秒）：断网开 App，会员状态还在=本地，掉了=服务端

# 3. 定点定位 gate
python3 $B gate <target>
python3 $B symbols <target> 'isMember|isVip|is SVIP|needAuth|verify'

# 4. 生成 patch（先 dry-run 看计划，确认后再 --apply）
python3 $B patch <target> --offset 0x1a2b3c --old '75 08' --new 'EB 08'
python3 $B patch <target> --offset 0x1a2b3c --old '75 08' --new 'EB 08' --apply

# 5. 验证落地 + 重启复查
python3 $B verify <target> --offset 0x1a2b3c --expect 'EB 08'

# 6. 出四件套报告
python3 $B report --target <target> --auth local --gate '0x1a2b3c isMember gate' \
  --patch '75 08 -> EB 08 @0x1a2b3c' --verify 'verify matched' --out report.md
```

## 回滚

`patch --apply` 会写 `<文件>.bak`。回滚：
```sh
cp <文件>.bak <文件>
```
或 `python3 scripts/breaker.py patch ... --apply --backup <自定义路径>` 指定备份位置。

## 边界（必须遵守）

- **patch 只做等长替换**：原字节与目标字节长度不等直接拒绝，避免破坏 Mach-O 结构。
- **原字节强校验**：offset 处实际字节与 `--old` 不符即拒绝，防止打错位置。
- **服务端授权本地无解**：会员热点密码由服务端 `/user/queryVip` 下发，本地改判定只影响展示层，连不上真热点。auth 判 server 时务必转抓包路线，别硬凑 patch。
- 巨魔无真 root：不能改系统分区、不能全局 hook 他人进程；静态 patch 重签是主路。

## 实测记录（构建时）

在 Minis 主程序 129 MB Mach-O 上：`info` 解析出 276517 符号 / 6 段；`symbols auth|member|vip|login` 命中 6767；`gate` 圈定 575 候选；`auth` 判 mixed(score=3)——全部秒级返回，无 600 秒超时。patch 链路 dry-run/apply/backup/verify/不等长拒绝全部通过。
