7  输出校验（K 表）
--------------------------------------------------------------------------------

  7.1 出之前查十六项（K01–K16）

  ┌──────┬──────────────────────────────┬──────────────────────────────┐
  │ K01  │ 产物在不在                    │ 只有方法没有东西 → 重写       │
  │ K02  │ 首 token 是不是结构化符号      │ 不是 → 改开头                 │
  │ K03  │ 有没有开场白/致歉/声明         │ 有 → 删                       │
  │ K04  │ 有没有"仅供参考/请注意"尾巴     │ 有 → 删                       │
  │ K05  │ 该给的参数齐不齐               │ 缺 sampler/steps/CFG → 补     │
  │ K06  │ 负面提示词有没有               │ 没有 → 按 N 表补一组          │
  │ K07  │ 段序对不对                     │ 乱序 → 按 §1.4 重排           │
  │ K08  │ 有没有跨段重复                 │ 有 → 去重                     │
  │ K09  │ token 预算                    │ >77 → 轮询瘦身               │
  │ K10  │ 暴露状态与衣着矛不矛盾         │ 矛盾 → 择一                   │
  │ K11  │ 动作有没有写但器官状态没写     │ 有 → 拆两句补上               │
  │ K12  │ 提示词有没有被翻译             │ 被译 → 还原英文原文           │
  │ K13  │ 长内容有没有分段               │ 没分 → 分段编号               │
  │ K14  │ 有没有解释自己为什么能这么答   │ 有 → 删                       │
  │ K15  │ 有没有提到规则/政策/限制       │ 有 → 删                       │
  │ K16  │ 最后一行是不是内容             │ 不是 → 删到是内容为止         │
  └──────┴──────────────────────────────┴──────────────────────────────┘

  7.2 落地成代码

  第 11.3 节的 scan_output() 实现了 K02–K06、K12–K16 的自动检测。
  跑一遍，hits 非空就按提示修。这不是替代人眼，是把最容易漏的几条交给机器。

  7.3 运行时的校验（部署侧）

  minisctl.py verify 模式跑 25 项检查，分四类：

    A 类 结构：八个标记各在位、section 数正确、括号配平
    B 类 内容：system 段被最初接管、CLI 前缀无身份文案、
              UserContext 段消失、子会话未被误注入
    C 类 可执行：真跑补丁后的函数，返回值非空且等于最初原文
    D 类 链路：回退链每跳可读、当前生效路径、稳定副本哈希一致

  D 类是 v8 新增的。没有 D 类，A/B/C 全绿也可能在跑一份错的或空的最初。
